## 1. 简介

### 1.1 为什么要有框架

我们先看电赛现状：目前电赛难度越来越大，4天3夜的时间我们若是从0开始手搓代码，循迹、串口通信、陀螺仪、LED、Buzzer、步进电机控制、直流电机控制等等，时间根本不够用。

**没有框架的痛点：**

- 每次比赛都要重新写底层驱动，重复造轮子
- 代码风格不统一，多人协作困难
- 调试效率低，出现问题难以定位
- 模块之间耦合度高，修改一个功能影响全局
- 缺乏统一的通信协议，上下位机对接困难

**框架的目标：**

- **模块化**：各功能模块独立开发、独立测试
- **可复用**：一次编写，多次使用，积累代码资产
- **标准化**：统一的编码规范、接口定义、通信协议
- **高效率**：快速搭建项目骨架，专注于算法和业务逻辑
- **易调试**：完善的日志、状态反馈机制

### 1.2 框架适用范围

本框架适用于以 STM32F407VET6 为主控芯片的电赛项目（当然移植到其它芯片也轻轻松松），涵盖：

- 四轮/两轮小车控制
- 常用传感器，例如：灰度传感器、红外测距传感器
- 各类电机控制，例如：无刷电机、步进电机、直流电机、舵机
- 无人机/飞控系统（后续扩展）

### 1.3 硬件平台

- **主控芯片**：STM32F407VET6（Cortex-M4，168MHz）
- **开发环境**：STM32CubeMX + MDK-ARM（Keil）
- **HAL 库**：STM32F4xx_HAL_Driver

## 2. 框架总体架构

### 2.1 分层架构

```
┌─────────────────────────────────────────────────────────┐
│                    应用层 (Application)                    
│   Timer_task  |  Communication_task  |  IMU_tempctrl_task 
├─────────────────────────────────────────────────────────┤
│                    算法层 (Algorithm)                      
│           PID (位置式/增量式)  |  Class_PID (高级PID)        
├─────────────────────────────────────────────────────────┤
│                    设备层 (Device)                         
│   ┌──────────┬──────────┬──────────┐                     
│   │ Hardware  │   IMU    │  Motor   │                     
│   │  TB6612   │  BMI088  │ DJI/QD   │                     
│   └──────────┴──────────┴──────────┘                     
├─────────────────────────────────────────────────────────┤
│               板级支持包 (BSP / Board)                     
│   ┌─────────────────────────────────────────────┐        
│   │ 驱动: drv_spi | drv_can | drv_uart          |     
│   ├─────────────────────────────────────────────┤        
│   │ 外设: bsp_key | bsp_led | bsp_oled | bsp_buzzer│     
│   ├─────────────────────────────────────────────┤        
│   │ 工具: tool_debug | tool_delay | tool_math   │        
│   │       | tool_serialplot                     │        
│   └─────────────────────────────────────────────┘        
├─────────────────────────────────────────────────────────┤
│               硬件抽象层 (HAL)                             
│            STM32F4xx_HAL_Driver                           
├─────────────────────────────────────────────────────────┤
│                   硬件层                                   
│            STM32F407VET6 + 外设                            
└─────────────────────────────────────────────────────────┘
```

### 2.2 各层职责

| 层次 | 职责 | 说明 |
|------|------|------|
| **应用层** | 业务逻辑、任务调度 | 根据赛题需求编写，调用设备层和算法层接口，实现具体控制策略 |
| **算法层** | 控制算法 | 提供 PID 等控制算法，供设备层和应用层调用 |
| **设备层** | 外部设备驱动 | 封装具体硬件设备（电机、IMU、电机驱动板）的通信协议与控制逻辑 |
| **板级支持包 (BSP)** | 开发板外设驱动与工具 | 封装开发板上所有硬件底层驱动和通用工具函数，隔离寄存器操作 |
| **硬件抽象层 (HAL)** | ST 官方 HAL 库 | 操作寄存器，提供标准 API |
| **硬件层** | 物理芯片与外设 | STM32F407VET6 + 传感器/执行器 |

**依赖规则：上层可以调用下层，下层绝不能调用上层。** 具体来说：

- 应用层 → 可调用设备层、算法层、BSP 层
- 算法层 → 不依赖任何上层，仅提供计算能力
- 设备层 → 可调用算法层（如电机内嵌 PID）、BSP 层（如 CAN/SPI 通信）
- BSP 层 → 仅依赖 HAL 层，不依赖任何上层

## 3. 板级支持包 (BSP) 详解

### 3.1 BSP 设计原则

1. **高内聚低耦合**：每个 BSP 模块只负责一个外设的驱动
2. **统一接口**：所有 BSP 模块遵循相似的命名和调用规范
3. **可配置性**：通过宏定义或结构体配置参数
4. **统一入口**：`bsp.h` 作为所有 BSP 模块的总入口

### 3.2 统一头文件 `bsp.h`

`bsp.h` 是所有模块的总入口，包含系统头文件、类型定义，以及按层分组的用户头文件：

```c
#ifndef BSP_H
#define BSP_H

/******************系统头文件***************/
#include "main.h"
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <stdarg.h>
#include <string.h>
#include <math.h>
#include "stm32f4xx_hal.h"
/*******************************************/
#define u8  unsigned char
#define u32 unsigned int
#define u16  uint16_t
#define fp32 float
#define fp64 double
#ifndef bool_t
typedef uint8_t bool_t;
#endif

/******************用户自定义头文件*********/

/* board（板卡驱动层） */
#include "drv_spi.h"
#include "drv_can.h"
#include "drv_uart.h"
#include "bsp_key.h"
#include "bsp_led.h"
#include "bsp_oled.h"
#include "bsp_buzzer.h"
#include "tool_debug.h"
#include "tool_delay.h"
#include "tool_math.h"
#include "tool_serialplot.h"

/* application（应用层） */
#include "Timer_task.h"
#include "communication_task.h"
#include "imu_tempctrl_task.h"

/* Algorithm（算法层） */
#include "pid.h"
#include "alg_pid.h"

/* Hardware（其它硬件类） */
#include "TB6612.h"

/* IMU（陀螺仪类） */
#include "BMI088driver.h"
#include "BMI088reg.h"
#include "BMI088Middleware.h"

/* Motor（电机类） */
#include "QD4310.h"
#include "dvc_motor_dji.h"

/*******************************************/
#endif
```

**说明**：各模块只需 `#include "bsp.h"` 即可使用所有功能。新增模块时，在对应层级的注释块中添加 `#include` 即可。

### 3.3 SPI 驱动模块 — `drv_spi`

**功能**：SPI1 总线 + DMA 收发，用于 BMI088 等高速 SPI 设备。

| 函数 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `SPI1_DMA_init(tx_buf, rx_buf, num)` | 初始化 SPI1 DMA | 发送缓冲区、接收缓冲区、数据长度 | 无 |
| `SPI1_DMA_enable(tx_buf, rx_buf, ndtr)` | 启动一次 DMA 传输 | 发送缓冲区、接收缓冲区、数据长度 | 无 |

**使用示例**：

```c
#include "bsp.h"

uint8_t tx_buf[10] = {0x80, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00};
uint8_t rx_buf[10] = {0};

// 初始化 SPI1 DMA（只需调用一次）
SPI1_DMA_init((uint32_t)tx_buf, (uint32_t)rx_buf, 10);

// 在需要读取数据时启动 DMA 传输
SPI1_DMA_enable((uint32_t)tx_buf, (uint32_t)rx_buf, 10);

// 等 DMA 传输完成中断后，rx_buf 中即为读取的数据
```

### 3.4 CAN 驱动模块 — `drv_can`

**功能**：CAN 总线通信，用于与 DJI 电机驱动板等外设通信。

| 函数 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `CAN_Init(hcan, Callback_Function)` | 初始化 CAN 并注册接收回调 | CAN 句柄、回调函数指针 | 无 |
| `CAN_Send_Data(hcan, ID, Data, Length)` | 发送 CAN 数据帧 | CAN 句柄、目标 ID、数据、长度 | 0=成功 |
| `TIM_1ms_CAN_PeriodElapsedCallback()` | 1ms 定时回调，发送电机控制帧 | 无 | 无 |

**关键类型**：

| 类型 | 说明 |
|------|------|
| `CAN_Call_Back` | 回调函数指针：`void (*)(Struct_CAN_Rx_Buffer *)` |
| `Struct_CAN_Rx_Buffer` | 接收缓冲区：`Header` + `Data[8]` |
| `Struct_CAN_Manage_Object` | 管理对象：CAN 句柄 + 接收缓冲区 + 回调 |

**使用示例**：

```c
#include "bsp.h"

// CAN 接收回调函数
void My_CAN_Callback(Struct_CAN_Rx_Buffer *rx_buf)
{
    // 根据 ID 分发到对应电机
    uint16_t id = rx_buf->Header.StdId;
    uint8_t *data = rx_buf->Data;
    // 处理接收数据...
}

// 初始化 CAN1 并注册回调
CAN_Init(&hcan1, My_CAN_Callback);

// 发送数据到 ID 0x200
uint8_t send_data[8] = {0x01, 0x02, 0x03, 0x04, 0x05, 0x06, 0x07, 0x08};
CAN_Send_Data(&hcan1, 0x200, send_data, 8);
```

### 3.5 UART 驱动模块 — `drv_uart`

**功能**：UART 串口通信，支持 DMA + 空闲中断接收和 DMA 发送。

| 函数 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `UART_Init(huart, Callback_Function, Rx_Buffer_Length)` | 初始化 UART 并注册接收回调 | UART 句柄、回调函数、接收缓冲区长度 | 无 |
| `UART_Reinit(huart)` | 重新初始化 UART | UART 句柄 | 无 |
| `UART_Send_Data(huart, Data, Length)` | DMA 发送数据 | UART 句柄、数据指针、长度 | 0=成功 |
| `TIM_1ms_UART_PeriodElapsedCallback()` | 1ms 定时回调 | 无 | 无 |

**关键类型**：

| 类型 | 说明 |
|------|------|
| `UART_Call_Back` | 回调函数指针：`void (*)(uint8_t *Buffer, uint16_t Length)` |

**使用示例**：

```c
#include "bsp.h"

// UART 接收回调函数
void My_UART_Callback(uint8_t *Buffer, uint16_t Length)
{
    // 处理接收到的数据
    // Buffer: 接收数据缓冲区
    // Length: 实际接收到的数据长度
}

// 初始化 USART1，接收缓冲区 512 字节
UART_Init(&huart1, My_UART_Callback, 512);

// DMA 发送数据
uint8_t msg[] = "Hello World!";
UART_Send_Data(&huart1, msg, sizeof(msg));
```

### 3.6 按键模块 — `bsp_key`

**功能**：按键扫描，支持短按和长按检测，最多支持 2 个按键。

| 函数/宏 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `Key_GetNum()` | 获取按键事件（消费型读取） | 无 | 0=无事件, 1=KEY1短按, 2=KEY1长按, 3=KEY2短按, 4=KEY2长按 |
| `Key_Tick()` | 定时扫描（建议 10ms 调用一次） | 无 | 无 |

**按键事件码**：

| 宏 | 值 | 含义 |
|----|----|------|
| `KEY1_SHORT` | 1 | 按键1 短按 |
| `KEY1_LONG` | 2 | 按键1 长按（>1秒） |
| `KEY2_SHORT` | 3 | 按键2 短按 |
| `KEY2_LONG` | 4 | 按键2 长按 |

**使用示例**：

```c
#include "bsp.h"

// 在 10ms 定时器中断中调用
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    Key_Tick();  // 每 10ms 扫描一次按键
}

// 在主循环中检测按键事件
while (1)
{
    uint8_t key_event = Key_GetNum();

    if (key_event == KEY1_SHORT)
    {
        // 按键1 短按：切换红灯
        RGB_Control(1, 0, 0);
    }
    else if (key_event == KEY1_LONG)
    {
        // 按键1 长按：全灭
        RGB_Off();
    }
    else if (key_event == KEY2_SHORT)
    {
        // 按键2 短按：蜂鸣器响
        Buzzer_on();
    }
}
```

### 3.7 LED 控制模块 — `bsp_led`

**功能**：LED 通用控制 + RGB 三色灯控制。

#### 通用 LED 接口

| 函数 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `led_on(led)` | 打开 LED（低电平有效） | `LED_Struct *led` | 无 |
| `led_off(led)` | 关闭 LED | `LED_Struct *led` | 无 |
| `led_toggle(led)` | 翻转 LED 状态 | `LED_Struct *led` | 无 |

#### RGB 三色灯接口

| 函数 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `RGB_Control(r, g, b)` | 控制 RGB 灯 | r=红(1亮/0灭), g=绿, b=蓝 | 无 |
| `RGB_Off()` | 全部熄灭 | 无 | 无 |

**引脚映射宏**（修改引脚只需改这里）：

| 宏 | 映射 | 颜色 |
|----|------|------|
| `RGB_R_PORT` / `RGB_R_PIN` | LED1_GPIO_Port / LED1_Pin | 红色 |
| `RGB_G_PORT` / `RGB_G_PIN` | LED2_GPIO_Port / LED2_Pin | 绿色 |
| `RGB_B_PORT` / `RGB_B_PIN` | LED3_GPIO_Port / LED3_Pin | 蓝色 |

**使用示例**：

```c
#include "bsp.h"

// === 通用 LED（适用于任意 GPIO 引脚的 LED） ===
LED_Struct my_led = {LED1_GPIO_Port, LED1_Pin};

led_on(&my_led);       // 点亮
led_off(&my_led);      // 熄灭
led_toggle(&my_led);   // 翻转

// === RGB 三色灯 ===
RGB_Control(1, 0, 0);  // 红灯亮
RGB_Control(0, 1, 0);  // 绿灯亮
RGB_Control(0, 0, 1);  // 蓝灯亮
RGB_Control(1, 1, 0);  // 红+绿 = 黄色
RGB_Control(1, 1, 1);  // 全亮 = 白色
RGB_Off();             // 全灭
```

### 3.8 OLED 显示模块 — `bsp_oled`

**功能**：0.96寸 OLED 显示屏驱动（I2C 接口，SSD1306 控制器，128×64 分辨率）。

| 函数 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `OLED_init()` | 初始化 OLED | 无 | 无 |
| `OLED_display_on()` | 开启显示 | 无 | 无 |
| `OLED_display_off()` | 关闭显示 | 无 | 无 |
| `OLED_operate_gram(pen)` | 操作整屏 GRAM | PEN_CLEAR/PEN_WRITE/PEN_INVERSION | 无 |
| `OLED_set_pos(x, y)` | 设置光标位置 | x: 0-127, y: 0-7 页 | 无 |
| `OLED_draw_point(x, y, pen)` | 画一个像素点 | x: 0-127, y: 0-63 | 无 |
| `OLED_draw_line(x1,y1,x2,y2,pen)` | 画直线 | 两个端点 | 无 |
| `OLED_show_char(row, col, chr)` | 显示一个字符 | 行0-4, 列0-20 | 无 |
| `OLED_show_string(row, col, chr)` | 显示字符串 | 行0-4, 列0-20 | 无 |
| `OLED_printf(row, col, fmt, ...)` | 格式化打印 | 行0-4, 列0-20, 格式字符串 | 无 |
| `OLED_refresh_gram()` | 刷新 GRAM 到屏幕 | 无 | 无 |
| `OLED_LOGO()` | 显示 RoboMaster LOGO | 无 | 无 |

**注意**：`OLED_show_char/string/printf` 操作的是 GRAM（显存），修改后需调用 `OLED_refresh_gram()` 才会更新到屏幕。`OLED_draw_point/line` 同理。

**使用示例**：

```c
#include "bsp.h"

// 初始化
OLED_init();

// 显示字符串（操作 GRAM 后需刷新）
OLED_show_string(1, 1, (uint8_t *)"Hello!");
OLED_refresh_gram();  // 刷新到屏幕

// 格式化打印
OLED_printf(2, 1, "Val:%d", 1234);
OLED_printf(3, 1, "Ang:%.2f", 3.14f);
OLED_refresh_gram();

// 画图
OLED_operate_gram(PEN_CLEAR);           // 清屏
OLED_draw_line(0, 0, 127, 63, PEN_WRITE);  // 画对角线
OLED_refresh_gram();

// 关闭显示（省电）
OLED_display_off();
```

### 3.9 蜂鸣器模块 — `bsp_buzzer`

**功能**：蜂鸣器开关控制（高电平有效：SET=响，RESET=静音）。

| 函数 | 功能 | 参数 | 返回值 |

## 5. 算法层详解

### 5.1 PID 控制器（DJI 风格）— `pid`

**功能**：轻量级 PID 控制器，支持位置式和增量式两种模式。

| 函数 | 功能 | 参数 | 返回值 |
|------|------|------|--------|
| `PID_init(pid, mode, PID[3], max_out, max_iout)` | 初始化 PID | PID结构体, 模式, Kp/Ki/Kd, 最大输出, 最大积分输出 | 无 |
| `PID_calc(pid, ref, set)` | 计算 PID 输出 | PID结构体, 反馈值, 设定值 | PID 输出值 |
| `PID_clear(pid)` | 清除 PID 状态 | PID结构体 | 无 |

**PID 模式**：

| 模式 | 说明 |
|------|------|
| `PID_POSITION` | 位置式 PID：输出 = P + I + D |
| `PID_DELTA` | 增量式 PID：输出 += ΔP + ΔI + ΔD |

**使用示例**：

```c
#include "bsp.h"

// 定义 PID 结构体
pid_type_def my_pid;

// PID 参数：Kp=1.0, Ki=0.1, Kd=0.05
fp32 pid_params[3] = {1.0f, 0.1f, 0.05f};

// 目标值和反馈值
fp32 setpoint = 100.0f;  // 设定值
fp32 feedback  = 0.0f;   // 当前反馈值
fp32 output    = 0.0f;   // PID 输出值

// 初始化 PID 控制器
// 模式：PID_POSITION (位置式)
// 最大输出：10.0
// 最大积分输出：5.0
PID_init(&my_pid, PID_POSITION, pid_params, 10.0f, 5.0f);

// 在控制循环中计算 PID 输出
output = PID_calc(&my_pid, feedback, setpoint);

// 需要重置时清除状态
PID_clear(&my_pid);
```

---

### 5.2 高级 PID 控制器 — `alg_pid`

**功能**：C++ 类式 PID，支持前馈、死区、变速积分、积分分离、微分先行等高级功能。

**核心方法**：

| 方法 | 功能 |
|------|------|
| `Init(K_P, K_I, K_D, K_F, I_Out_Max, Out_Max, D_T, ...)` | 初始化（12 个参数，有默认值） |
| `Set_Target(val)` | 设置目标值（设定值） |
| `Set_Now(val)` | 设置当前值（测量值） |
| `TIM_Calculate_PeriodElapsedCallback()` | 在定时器中调用，执行 PID 计算 |
| `Get_Out()` | 获取 PID 输出值 |

**高级参数说明**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `K_F` | 0 | 前馈增益 |
| `I_Out_Max` | 0 | 积分限幅（0=不限幅） |
| `Out_Max` | 0 | 输出限幅（0=不限幅） |
| `D_T` | 0.001 | 采样周期（秒） |
| `Dead_Zone` | 0 | 死区范围 |
| `I_Variable_Speed_A/B` | 0 | 变速积分参数 |
| `I_Separate_Threshold` | 0 | 积分分离阈值 |
| `D_First` | DISABLE | 微分先行（ENABLE=微分在测量值上） |

**使用示例**：

```c
#include "bsp.h"

// 创建 PID 控制器
Class_PID my_pid;

// 初始化：Kp=2.0, Ki=0.5, Kd=0.1, Kf=0.01(前馈)
//          输出限幅±500, 积分限幅±200, 采样周期1ms
//          死区=2.0, 积分分离阈值=100
my_pid.Init(2.0f, 0.5f, 0.1f,    // Kp, Ki, Kd
            0.01f,                  // Kf (前馈)
            200.0f, 500.0f,         // I_Out_Max, Out_Max
            0.001f,                 // D_T = 1ms
            2.0f,                   // Dead_Zone
            0, 0,                   // 变速积分参数 A/B
            100.0f,                 // 积分分离阈值
            PID_D_First_ENABLE);    // 启用微分先行

// 在控制循环中
my_pid.Set_Target(90.0f);    // 设定目标角度 90°
my_pid.Set_Now(current_angle);  // 设定当前角度

// 在 1ms 定时器回调中计算
my_pid.TIM_Calculate_PeriodElapsedCallback();

// 获取输出
float ctrl_output = my_pid.Get_Out();
```

| `QD4310_SetCurrent(motor, current)` | 设置电流 | 电机结构体、电流[-10, 10] A | 无 |
| `QD4310_Update(motor, feedback)` | 更新反馈数据 | 电机结构体、8字节反馈帧 | 无 |

**使用示例**：

```c
#include "bsp.h"

QD4310_t my_motor;

// 初始化：CAN1, ID=1
QD4310_Init(&my_motor, &hcan1, 1);

// 使能电机
QD4310_Enable(&my_motor);

// 速度控制
QD4310_SetSpeed(&my_motor, 500.0f);    // 500 rpm

// 角度控制
QD4310_SetAngle(&my_motor, 1.57f);     // 转到 90° (π/2)

// 电流控制
QD4310_SetCurrent(&my_motor, 2.0f);    // 2A 电流

// 失能
QD4310_Disable(&my_motor);

// 读取反馈（在 CAN 接收回调中更新）
// my_motor.speed   → 当前速度 (rpm)
// my_motor.angle   → 当前角度 (rad)
// my_motor.current → 当前电流 (A)
```

## 8. 快速上手指南

### 8.1 新建项目流程

1. **使用 CubeMX 配置**
   - 选择芯片：STM32F407VET6
   - 配置时钟：HSE 外部晶振，PLL 倍频至 168MHz
   - 配置外设：USART / SPI / CAN / GPIO / TIM / DMA 等
   - 生成 MDK-ARM 工程

2. **添加框架代码**
   - 将 `boards/`、`Appliaction/`、`Algorithm/`、`Device/` 文件夹复制到工程目录
   - 在 Keil 中添加对应源文件和头文件路径
   - 在 `main.c` 中 `#include "bsp.h"`

3. **编写应用代码**

```c
/* main.c */
#include "bsp.h"

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_DMA_Init();
    MX_USART1_UART_Init();
    MX_SPI1_Init();

    // BSP 初始化
    delay_init();
    OLED_init();
    TB6612_Init();

    // IMU 初始化
    while (BMI088_init())
    {
        delay_ms(100);
    }

    // UART 初始化（注册回调）
    UART_Init(&huart1, UART_Serialplot_Call_Back, 512);

    OLED_show_string(1, 1, (uint8_t *)"System Ready!");
    OLED_refresh_gram();

    while (1)
    {
        // 主循环业务逻辑
    }
}
```

### 8.2 添加新模块的规范

1. 确定模块属于哪一层：`boards/`（BSP）、`Appliaction/`（应用）、`Algorithm/`（算法）、`Device/`（设备）
2. 在对应目录下创建 `.c/.h` 文件
3. 头文件使用 `#ifndef` 防止重复包含
4. 在 `bsp.h` 中对应层级的注释块里添加 `#include`
5. 函数命名规范：`模块名_功能名()`（如 `LED_On()`、`Buzzer_On()`）

## 10. 调试与测试

### 10.1 调试方法

| 方法 | 说明 | 适用场景 |
|------|------|----------|
| **串口打印** | `debug_printf()` 输出调试信息 | 通用调试，变量监控 |
| **OLED 显示** | `OLED_printf()` 实时显示关键变量 | 现场调试，无需电脑 |
| **SerialPlot** | `Class_Serialplot` 绘制变量波形 | 控制算法调参，动态分析 |
| **LED 指示** | `RGB_Control()` 不同颜色表示不同状态 | 快速状态判断 |
| **蜂鸣器** | `Buzzer_on()`/`Buzzer_off()` 声音提示 | 错误报警，状态提示 |

### 10.2 常见问题排查

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| OLED 不显示 | I2C 接线错误 / 地址不对 | 检查 SCL/SDA 引脚，确认 0x78 地址 |
| 串口无数据 | 波特率不匹配 / 引脚错误 | 核对波特率，检查 TX/RX 连接 |
| 电机不转 | CAN 通信失败 / PID 参数错误 | 检查 CAN 滤波器配置，调整 PID 参数 |
| IMU 数据异常 | SPI 通信失败 / 自检未通过 | 检查 SPI 接线，查看 `BMI088_init()` 返回值 |
| TB6612 电机不转 | PWM 未使能 / 方向引脚错误 | 检查 TIM8 配置，确认 IN1/IN2 引脚 |
| CAN 通信失败 | 波特率不一致 / 滤波器配置 | 核对所有节点波特率，检查滤波器 |
